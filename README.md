# ProSafe Portal

Статический портал HR с авторизацией Supabase и ролевым доступом.

## Что включено
- статические страницы HTML/CSS/JS
- локальное сохранение отдельных HR-функций, ещё не подключённых к серверу
- страница входа с отдельным кабинетом сотрудника
- общая дизайн-система экранов и адаптивная прокрутка таблиц на узких экранах
- сохранение выбранной темы оформления в боковом меню
- GitHub Pages deployment workflow
- Supabase/PostgreSQL schema for employee directory, company history, FAQ and searchable documents/templates
- скачивание пустого CSV-шаблона плана адаптации и импорт заполненного плана в шаблон выбранной должности

## Вход и роли
Вход выполняется через Supabase Auth по корпоративной почте и паролю. Роль и связь с профилем сотрудника загружаются из `public.profiles`; доступ к строкам базы данных дополнительно ограничен RLS. Тестовых кнопок входа и фиктивных ролей в клиенте нет.

Создание сотрудника и изменение доступа выполняются Edge Function `manage-employee`, которая проверяет пользователя и его роль HR на сервере. Список сотрудников, подразделения, контакты, FAQ и опубликованные материалы загружаются из Supabase. Файлы материалов скачиваются из закрытого Storage bucket по временным подписанным ссылкам.

Выбор темы находится в боковом меню HR и сотрудника. Доступны стандартный дизайн ProSafe и тема «Дофаминовый декор»; выбранная тема сохраняется на устройстве.

В HR-кабинете есть пункт «Моя визитка». В справочнике HR может редактировать карточки сотрудников и задачи их индивидуальных планов; на главной показываются задачи адаптации, назначенные на текущий день, а название задачи открывает редактор. Сотрудники могут просматривать историю компании, оргструктуру и FAQ, искать и скачивать доступные документы и шаблоны, оставлять анонимные идеи и отправлять личные обращения HR. На главной сотрудника показываются его задачи на сегодня и открытые поручения, где он назначен ответственным. HR просматривает анонимные идеи и обращения в разделе «Опросы и результаты → Сообщения сотрудников».

Редактирование карточек сотрудников, планы адаптации, шаблоны должностей, опросы, ответы, идеи, обратная связь и часть HR-операций пока сохраняются только в браузере и не синхронизируются между пользователями. Не используйте эти локальные функции для персональных или конфиденциальных производственных данных.

В разделе «Управление адаптацией → План адаптации» доступен CSV-импорт шаблонов, проверка дней адаптации и времени. Этот функционал пока использует локальное хранилище браузера; загружаемые шаблоны не синхронизируются с Supabase.

## Supabase: схема базы данных

Структура и RLS находятся в [`supabase/schema.sql`](./supabase/schema.sql); файл создаёт таблицы и закрытый Storage bucket, но не добавляет тестовые записи. Не запускайте схему повторно на уже используемой базе без проверки SQL. Для существующего проекта сначала примените нужные изменения из [`supabase/migrations/`](./supabase/migrations/). Образцы вымышленных данных вынесены в [`supabase/seed-demo.sql`](./supabase/seed-demo.sql): запускать его можно только в отдельном disposable-проекте, не в production.

1. Создайте проект в Supabase.
2. Для нового, пустого Supabase-проекта откройте `SQL Editor -> New query`, проверьте содержимое `supabase/schema.sql` и выполните его. Для уже существующей базы не запускайте всю схему повторно: проверьте, какие миграции из `supabase/migrations/` ещё не применялись, и выполняйте только их.
   URL и publishable key текущего проекта настроены в `js/app.js`. Publishable key предназначен для браузера и не даёт административных прав. Проверить создание таблиц можно так:

   ```sql
   select to_regclass('public.org_units') as org_units,
          to_regclass('public.employees') as employees,
          to_regclass('public.materials') as materials;
   ```

   Для всех трёх полей ожидаются имена таблиц, не `NULL`.
3. Создайте первого пользователя HR в `Authentication -> Users`, затем в SQL Editor свяжите его с профилем (замените email на адрес созданного пользователя):

   ```sql
   insert into public.profiles (id, role)
   select id, 'hr' from auth.users where email = 'hr@example.com'
   on conflict (id) do update set role = excluded.role;
   ```

   Для сотрудника с адаптацией вручную создавать связь не нужно: HR создаёт сотрудника из портала. Если нужно привязать уже существующий профиль, сопоставьте email пользователя с контактным email сотрудника:

   ```sql
   insert into public.profiles (id, role, employee_id)
   select auth_user.id, 'employee_onboarding', employee.id
   from auth.users auth_user
   join public.employee_contacts contact on lower(contact.email) = lower(auth_user.email)
   join public.employees employee on employee.id = contact.employee_id
   where auth_user.email = 'employee@example.com'
   on conflict (id) do update
   set role = excluded.role, employee_id = excluded.employee_id;
   ```

   Используйте `employee` для обычного сотрудника и `adaptation_manager` для руководителя адаптации. Роль HR должна назначаться только из доверенной административной среды.
4. Установите Supabase CLI, выполните `supabase link --project-ref zamkapigzsqgzfbblmjs`, добавьте service-role key как секрет Edge Function `SERVICE_ROLE_KEY` через Supabase Dashboard/CLI и разверните `supabase functions deploy manage-employee`. Этот секрет нельзя помещать в чат, Git, GitHub Pages или клиентский код. Функция создаёт пользователей и записи только после серверной проверки действующей сессии и роли HR.
5. Загрузите реальные PDF/DOCX-файлы в закрытый bucket `prosafe-documents` и добавьте записи материалов с путём объекта в `materials.storage_path`. Файлы и записи материалов не создаются схемой автоматически.
6. В настройках Supabase Auth задайте URL опубликованного сайта в `Site URL` и разрешённые redirect URLs. Убедитесь, что в Authentication включён вход по email и паролю.

Вход в портал, FAQ и материалы подключены к Supabase. История PROSAFE отображается как единая статическая страница в кабинетах HR и сотрудника; таблица `company_history` в схеме остаётся для совместимости, но эти экраны её не читают и не редактируют. Список сотрудников, доступы и оргструктура также загружаются из Supabase. Остальные данные (задачи адаптации, опросы, отклики и часть HR-операций) пока локальные. На клиент помещён только publishable key; `service_role` key нельзя помещать в HTML, JavaScript или GitHub Pages.

В кабинете сотрудника история, оргструктура, FAQ и документы/шаблоны доступны для просмотра и поиска. Они не показывают HR-кнопки редактирования; ветвь оргструктуры подсвечивается при наведении или клавиатурном фокусе.

## Запуск локально
Откройте проект в браузере через локальный сервер, например:

```bash
python -m http.server 8000
```

После этого откройте:

```text
http://localhost:8000/
```

## Развёртывание на GitHub Pages
1. Создайте репозиторий на GitHub.
2. Загрузите код в ветку `main`.
3. В настройках репозитория откройте `Settings -> Pages`.
4. Источник: `GitHub Actions`.
5. После push workflow автоматически задеплоит сайт.

Workflow публикует только HTML-страницы и папки `css/` и `js/`; SQL-схема и служебные файлы Supabase в Pages не попадают.

Сайт будет доступен по адресу:

```text
https://<username>.github.io/<repository-name>/
```
